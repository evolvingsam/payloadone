Developer Documentation

PayloadOne

A Python SDK that sits between incoming Paystack and Flutterwave webhook requests and your business logic. Automatic signature verification, a single normalised event model, and atomic idempotency — before a single line of your code runs.

BASE URL — DEMO   https://payloadone-demo.onrender.com
PYPI   pip install payloadone
LICENSE   MIT

Credentials Reference

Every credential you will need across both the live testing section and the SDK integration section, in one place.

Credential Where to get it Used for Format
Paystack Secret Key Paystack Dashboard → Settings → API Keys & Webhooks Signature verification (HMAC-SHA512) sk_test_xxxxxxxxxxxx
Flutterwave Secret Hash Flutterwave Dashboard → Settings → Webhooks → Secret Hash Signature verification (plain comparison) any string you set
Redis URL Your Redis instance (local or hosted) Idempotency ledger backend redis://localhost:6379/0
PostgreSQL DSN Your Postgres instance (optional alternative to Redis) Idempotency ledger backend postgresql://user:pass@host/db
Important Always use test mode credentials during development. Paystack test keys start with sk_test_. Flutterwave test keys start with FLWSECK_TEST-. These cannot move real money.
02

Live Testing — Environment Setup

The live demo is a hosted FastAPI app that has PayloadOne pre-configured. Point your Paystack or Flutterwave test webhook URL at it and watch events arrive in real time — no local setup required.

01

Get your Paystack test secret key

Log in to your Paystack account. Go to Settings → API Keys & Webhooks. Copy the value under Secret Key in the Test section. It starts with sk_test_.

Note If you do not have a Paystack account, register free at dashboard.paystack.com. No business verification is needed for test mode.
02

Get your Flutterwave secret hash

Log in to your Flutterwave account. Go to Settings → Webhooks. Under Secret Hash, enter any string of your choice — for example my_test_hash_123 — and save. This exact string is what PayloadOne compares against the verif-hash header on every inbound request.

03

Register your webhook URLs

In each dashboard, set the webhook URL to the live demo endpoints below.

POST https://payloadone-demo.onrender.com/webhooks/paystack
POST https://payloadone-demo.onrender.com/webhooks/flutterwave
Important The live demo uses its own configured test credentials. Webhooks from your dashboard will only verify correctly if they are sent in test mode using the demo's pre-configured keys. For testing with your own keys, run the demo locally — see Section 03.
03

Run the Demo Locally

Run the demo on your own machine so you can use your own credentials and inspect every log line in real time.

01

Prerequisites

You need Python 3.11+, pip, and Redis. Start Redis:

bash 
# Using Docker (recommended)
$ docker run -d -p 6379:6379 --name payloadone-redis redis:7-alpine

# Or natively on Ubuntu/WSL
$ sudo apt install redis-server && sudo service redis-server start

# Verify Redis is running
$ redis-cli ping
PONG
02

Clone the repository

bash 
$ git clone https://github.com/your-org/payloadone.git
$ cd payloadone
03

Create your environment file

Create a .env file inside the demo/ folder. Paste your actual test credentials — no quotes needed.

dotenv — demo/.env 
PAYSTACK_SECRET_KEY=sk_test_your_paystack_key_here
FLUTTERWAVE_SECRET_HASH=your_flutterwave_secret_hash_here
REDIS_URL=redis://localhost:6379/0
Never commit this file The demo/.env file is already listed in .gitignore. Do not remove it from there. Never paste real secret keys into source code.
04

Install dependencies and start the server

bash 
# Install the library and demo dependencies
$ pip install -e .
$ pip install -r demo/requirements.txt

# Load env vars and start — must be done in one command
# so the server process inherits them
$ export $(cat demo/.env | xargs) && uvicorn demo.main:app --reload --port 8000

You should see Uvicorn running on http://127.0.0.1:8000. Open http://localhost:8000/docs in your browser to access the interactive Swagger UI.

04

Send Test Webhooks

Use the commands below to simulate what Paystack and Flutterwave send to your server. Run these in a second terminal while the server is running.

01

Send a Paystack payment.success webhook

This generates a valid HMAC-SHA512 signature using your secret key and sends a charge.success event.

bash 
# Load your env vars in the new terminal first
$ export $(cat demo/.env | xargs)

# Build the payload
$ PAYLOAD='{"event":"charge.success","data":{"reference":"ref_001","amount":5000,"currency":"NGN","customer":{"email":"test@example.com","first_name":"Ada","last_name":"Obi"},"metadata":{}}}'

# Generate the HMAC-SHA512 signature
$ SIG=$(echo -n "$PAYLOAD" | openssl dgst -sha512 -hmac "$PAYSTACK_SECRET_KEY" | awk '{print $2}')

# Send the webhook
$ curl -s -X POST http://localhost:8000/webhooks/paystack \
  -H "Content-Type: application/json" \
  -H "x-paystack-signature: $SIG" \
  -d "$PAYLOAD"
200 OK
{"status": "acknowledged"}
02

Send a Flutterwave payment.success webhook

Flutterwave uses a plain secret hash — no HMAC computation needed. Use a Python script to avoid shell quoting issues on Windows/WSL.

bash — save as send_flw.py and run with python3 send_flw.py 
import urllib.request, json, os

url = "http://localhost:8000/webhooks/flutterwave"
payload = {
    "event": "charge.completed",
    "data": {
        "id": 1,
        "tx_ref": "ref_002",
        "amount": 50.00,
        "currency": "NGN",
        "status": "successful",
        "customer": {"email": "test@example.com", "name": "Ada Obi"},
        "meta": {},
    },
}
body = json.dumps(payload).encode()
req = urllib.request.Request(url, data=body, method="POST")
req.add_header("Content-Type", "application/json")
req.add_header("verif-hash", os.environ["FLUTTERWAVE_SECRET_HASH"].strip())
try:
    with urllib.request.urlopen(req) as r:
        print("Status:", r.status, r.read().decode())
except urllib.error.HTTPError as e:
    print("Error:", e.code, e.read().decode())

Test idempotency — send the same webhook twice

Send the exact same Paystack request again using the same SIG and PAYLOAD variables. The server returns 200 but the handler does not run a second time. Check /events — ref_001 appears only once.

What this proves Even if Paystack retries delivery 3 times, your wallet credit or order fulfilment logic executes exactly once.

SDK — Installation

Install PayloadOne via pip. Choose the extras that match your stack.

bash 
# Redis backend + FastAPI
$ pip install "payloadone[redis,fastapi]"

# Redis backend + Flask
$ pip install "payloadone[redis,flask]"

# PostgreSQL backend instead of Redis
$ pip install "payloadone[postgres,fastapi]"

# Everything
$ pip install "payloadone[all]"
Requirement Python 3.11 or higher is required. Check your version with python --version.
08

SDK — Configuration

All configuration is injected at initialisation time via PayloadOneConfig. Nothing is read from environment variables implicitly — you control the surface.

python 
from payloadone import PayloadOneConfig

config = PayloadOneConfig(
    secret_keys={
        # Your Paystack test secret key
        "paystack":    "sk_test_your_paystack_secret_key",
        # Your Flutterwave secret hash (the string you set in the dashboard)
        "flutterwave": "your_flutterwave_secret_hash",
    },
    idempotency_backend="redis",        # "redis" or "postgres"
    redis_url="redis://localhost:6379/0", # required when backend is "redis"
    idempotency_ttl_seconds=86400,      # 24 hours — how long to remember a reference
)
Best practice Read credentials from environment variables, never hardcode them. Use os.environ["PAYSTACK_SECRET_KEY"] in production.
PostgreSQL alternative If you prefer PostgreSQL over Redis, use idempotency_backend="postgres" and postgres_dsn="postgresql://user:pass@host/db". You must also create the idempotency table — see the README.

SDK — FastAPI Integration

01

Wire up the manager and exception handlers

python — main.py 
import os
from fastapi import FastAPI, Request
from payloadone import WebhookManager, PayloadOneConfig
from payloadone.models.event import UnifiedEvent
from payloadone.adapters.fastapi import install_exception_handlers, process_webhook

app = FastAPI()

config = PayloadOneConfig(
    secret_keys={
        "paystack":    os.environ["PAYSTACK_SECRET_KEY"],
        "flutterwave": os.environ["FLUTTERWAVE_SECRET_HASH"],
    },
    idempotency_backend="redis",
    redis_url=os.environ["REDIS_URL"],
)

manager = WebhookManager(config=config)

# Maps PayloadOne exceptions to HTTP 401 / 400 / 422 automatically
install_exception_handlers(app)
02

Register your business logic handlers

python 
@manager.on("payment.success")
async def handle_payment(event: UnifiedEvent) -> None:
    # event is verified, deduplicated, and normalised
    # amount_in_lowest_unit is always an int (kobo/cents), never a float
    await credit_user_wallet(event.reference, event.amount_in_lowest_unit)

@manager.on("transfer.success")
async def handle_transfer(event: UnifiedEvent) -> None:
    await mark_transfer_complete(event.reference)

@manager.on("payment.failed")
async def handle_failure(event: UnifiedEvent) -> None:
    await notify_user_of_failure(event.customer_email)
03

Add the webhook route

python 
@app.post("/webhooks/{provider}")
async def webhook(provider: str, request: Request):
    return await process_webhook(manager, provider, request)

Set your webhook URLs in each dashboard:

POST https://yourapp.com/webhooks/paystack
POST https://yourapp.com/webhooks/flutterwave

SDK — Flask Integration

python — app.py 
import os
from flask import Flask
from payloadone import WebhookManager, PayloadOneConfig
from payloadone.models.event import UnifiedEvent
from payloadone.adapters.flask import process_webhook_sync

app = Flask(__name__)

config = PayloadOneConfig(
    secret_keys={
        "paystack":    os.environ["PAYSTACK_SECRET_KEY"],
        "flutterwave": os.environ["FLUTTERWAVE_SECRET_HASH"],
    },
    idempotency_backend="redis",
    redis_url=os.environ["REDIS_URL"],
)

manager = WebhookManager(config=config)

@manager.on("payment.success")
async def handle_payment(event: UnifiedEvent) -> None:
    await credit_user_wallet(event.reference, event.amount_in_lowest_unit)

@app.post("/webhooks/<provider>")
def webhook(provider: str):
    return process_webhook_sync(manager, provider)

SDK — Writing Handlers

Handlers receive a UnifiedEvent that is already verified, deduplicated, and normalised. Write only business logic — no infrastructure concerns.

Handler contract Handlers must be async functions that accept a single UnifiedEvent argument and return None. If a handler raises an exception, the idempotency key is not committed and the event will be retried on next delivery.
python — all supported event types 
@manager.on("payment.success")
async def _(event: UnifiedEvent): ...

@manager.on("payment.failed")
async def _(event: UnifiedEvent): ...

@manager.on("transfer.success")
async def _(event: UnifiedEvent): ...

@manager.on("transfer.failed")
async def _(event: UnifiedEvent): ...

@manager.on("refund.processed")
async def _(event: UnifiedEvent): ...

@manager.on("charge.dispute.create")
async def _(event: UnifiedEvent): ...

SDK — UnifiedEvent Reference

Every handler receives a UnifiedEvent regardless of whether the webhook came from Paystack or Flutterwave.

Field Type Description
provider Provider Source gateway: "paystack" or "flutterwave"
event_type EventType Normalised event e.g. "payment.success"
reference str Unique transaction reference — used for idempotency
amount_in_lowest_unit int Amount in kobo (NGN) or cents (USD). Always an integer, never a float.
currency str ISO 4217 code e.g. "NGN", "USD"
customer_email EmailStr Validated email address of the customer
customer_name str | None Customer's full name if available
metadata dict Passthrough metadata from the original checkout
raw_payload dict The original unmodified provider payload for debugging
provider_event_id str | None The provider's own event or notification identifier
